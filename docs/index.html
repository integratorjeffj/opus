The name

Why it is called Opus.

An opus number is how a composer's work gets catalogued. Op. 27, No. 2 is not a description of the music — it is an identifier, assigned once, that lets anyone say precisely which piece they mean two hundred years later. Publishers have numbered works this way since the seventeenth century for one reason: without a catalogue, you cannot tell one copy of a thing from another.

That is this problem, moved down a level. A publisher does not only need to know which piece went out. They need to know which copy, to whom, under which order, on what date.

So Opus does for copies what opus numbers did for works. Every file it issues carries a name on the page and a row in the ledger, and stays identifiable for as long as it exists.

Where this started

The stamping was solved. Everything around it was not.

A working script already handled one file: run a command, type the buyer's name, get a stamped and locked PDF. It did the hard part well.

But a choral octavo is a score, a choral score, and an organ part. A band piece can be twenty parts. The buyer's name got typed once per file, and the twentieth one had a typo in it. Nobody noticed an order had arrived until they checked. And nothing was recorded, so a leaked copy led nowhere.

The pipeline

How an order becomes a licensed file.

Five stages, in order. Nothing is written to disk until stage four is approved.

01

Read the export

PayPal's activity CSV. Column names are matched by meaning rather than position, because PayPal has renamed its export headers several times over the years. Only completed payments survive: refunds, reversals, withdrawals, fees and pending rows are dropped before anyone sees the list.

02

Match the title to files

Evening Bells - PDF Download and EVENING BELLS (score & parts) resolve to the same catalog entry. Titles are normalized, then matched exact, then by containment, then fuzzy at 86% similarity. Anything below that is reported as unmatched rather than guessed at, because issuing the wrong piece is worse than issuing nothing.

03

Check the ledger

Transaction IDs already recorded as issued are skipped. This is the failure that would otherwise bite hardest: export date ranges overlap constantly, and without this check the same order quietly goes out twice under a fresh password.

04

Review

Every order with its match, file count and disposition. Ready rows are preselected; anything else explains itself. Nothing is written until this is approved.

05

Stamp, lock, log

Per file: the notice is merged into the page content stream, form fields are flattened, AES-256 encryption is applied with editing and copying blocked, and a ledger row is appended.

The record

One row per file, written the moment it is issued.

This is what the original script was missing entirely. It does three jobs at once: it makes a leaked copy traceable, it prevents duplicate issuance, and it is the publisher's own record of what has been licensed.

Honest limits

What the protection actually does.

It does

  • Print the licensee's name on every page, merged into the page content so it is not a separate object to select and delete
  • Rotate the notice to match landscape and rotated pages, so it always reads the same way up as the music
  • Block editing, text extraction, commenting and page re-assembly with AES-256
  • Open and print normally, with no password for the buyer

It does not

  • Stop screenshots, phone photos, or re-printing to a fresh PDF
  • Survive a determined attacker with the right tools
  • Replace a license agreement

No PDF tool does these things. The deterrent is the name on the page: a shared copy stays traceable to whoever shared it, which is the point.

Running it

A window for daily use, a command line for everything else.

The app window is how a publisher uses it. The command line is there for scripting, testing, and dry runs.

# install
pip3 install pypdf reportlab pikepdf
python3 opus.py

# build a catalog map by scanning a folder of pieces
python3 opus.py --make-catalog ./catalog -o catalog_map.csv

# see what an export would produce, without writing anything
python3 opus.py --paypal examples/paypal_sample.csv \
    --catalog examples/catalog_map.csv --out ./licensed --dry-run

# a scripted run, confirming the demo-data terms up front
python3 opus.py --paypal examples/paypal_sample.csv     --catalog examples/catalog_map.csv --out ./licensed --demo-ack

Before the app window opens, a dialog asks you to confirm that what you are about to load is fictional or otherwise non-sensitive; nothing can be queued until it is ticked. On the command line the same confirmation is prompted for before anything is stamped — --dry-run is exempt, since it writes nothing, and --demo-ack or OPUS_DEMO_ACK=1 answers it for scripted runs. With no terminal to prompt at and no acknowledgement given, Opus refuses the run rather than assuming consent.

Python 3.9+. Built on pypdf, reportlab and pikepdf, with qpdf as an optional extra pass. MIT licensed.
